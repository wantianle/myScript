# Witt TUI 实施方案

## 目标

在保持 Python 3.8 基线不变的前提下，把当前 `witt` 从“脚本式 CLI”逐步升级为“更现代的终端交互工具”，但不引入需要 Python 3.9+ 的完整 TUI 框架。

核心目标：

- 保持现有 `core/` 业务逻辑尽量不动
- 渐进升级 `interface/` 层
- 优先提升可读性、可浏览性、可检索性
- 保持现有脚本链路和回播链路兼容
- 保持 Python 3.8 可运行

## 约束

- Python 基线必须兼容 `3.8`
- 当前不引入 `Textual`
  - 主要原因是其当前版本要求更高 Python 版本
- 当前仅使用仓库已有依赖体系
  - `rich`
  - `prompt-toolkit`
  - `questionary`
- 不重写 `core/`，不把 UI 逻辑下沉到业务层

## 选型结论

### 展示层

使用 `Rich`

原因：

- Python 3.8 可用
- 表格、面板、规则线、状态提示、颜色主题能力足够
- 适合渐进替换 `print(...)`
- 对现有流程侵入小

### 输入层

分阶段从 `questionary + input()` 迁移到 `prompt_toolkit`

原因：

- Python 3.8 可用
- 支持补全、快捷键、搜索、分页
- 适合历史浏览、选择器、增量搜索场景

### less 浏览

历史记录、长文本、日志类只读浏览优先继续使用 `less`

原因：

- 搜索能力强，用户成本低
- 比自建滚动视图便宜很多
- 当前终端环境可靠

## 交互范式更新

当前方案正式调整为：

- 主交互以“命令驱动 REPL”作为第一入口
- 菜单只作为过渡阶段的遗留实现，不再作为主方向

目标入口形态：

```text
Witt >
```

一条命令进入一个用例流，而不是先进入菜单树。

推荐一级命令：

- `help`
- `config`
- `slice`
- `full`
- `scan`
- `manual`
- `history`
- `traffic`
- `env`
- `clear`
- `quit`

基础子命令：

- `help <command>`
- `config`
- `history clear`
- `history last`
- `history <序号>`

## 总体架构

### 保持不动的层

- `core/`
- `utils/`
- `scripts/`

### 渐进改造的层

- `interface/ui.py`
- `interface/prompter.py`
- `interface/replay_prompter.py`
- `interface/cli.py`

### 目标状态

- `ui.py`
  - 只负责 Rich 展示
  - 不做输入采集
- `prompter.py`
  - 统一输入适配层
  - 未来逐步收口到 `prompt_toolkit`
- `workflow.py` / `replay_workflow.py`
  - 继续做用例编排
  - 不直接拼装复杂终端样式

## 分阶段实施

## 阶段 1：命令驱动入口 + Rich 展示层

### 目标

把顶层入口改成命令 REPL，同时升级展示层，但不改业务 workflow。

### 范围

- 主命令入口
- 主 banner
- 状态消息
- 回播库列表
- 回播信息面板
- 历史记录展示
- 手动模式头部提示
- 环境摘要页

### 具体改造

#### 1. 顶层入口

当前：

- `questionary` 菜单

目标：

- `Witt >` 命令提示符
- 顶层只做命令分发
- 命令背后继续复用现有 workflow

阶段 1 只做：

- 基础命令解析
- 命令别名
- 命令帮助
- 环境查看
- `config` 打开配置并重建会话
- 基础子命令
  - `history clear`
  - `history last`
  - `history <序号>`

#### 2. Banner

当前：

- 纯 `print("=" * 42)` 风格

目标：

- `Rich Panel` + `Rule`
- 保留工具名和版本号
- 视觉上更清晰

#### 3. 状态消息

当前：

- 手拼 ANSI 颜色

目标：

- 统一通过 `Rich Console.print`
- 用固定 style 映射：
  - `INFO`
  - `WARN`
  - `ERROR`

#### 4. 列表展示

当前：

- 手工对齐字符串

目标：

- `Rich Table`
- 自动列宽
- 便于后续接入搜索/筛选

适用页面：

- 自动扫描回播列表
- 历史记录列表

#### 5. 回播信息

当前：

- 逐行 `print`

目标：

- `Rich Panel`
- 统一展示：
  - tag
  - duration
  - rate
  - channels

#### 6. less 浏览内容

当前：

- 手工拼纯文本

目标：

- 保留 text 形式，便于 `less`
- 但文本格式由 `ui.py` 统一生成
- 通过 Rich 渲染为更清晰的文本块或表格后再交给 `less`

### 阶段 1 的完成标准

- 顶层入口变成命令 REPL
- 所有现有功能流程仍复用原 workflow
- 所有现有核心测试通过
- 新 UI 不依赖 Python 3.9+
- 去掉大部分手写 ANSI 字符串

## 阶段 2：输入层抽象与命令增强

### 目标

把输入采集从“散落的 `input()` + `questionary`”收成统一接口。

### 范围

- 命令输入
- yes/no 确认
- 历史记录序号输入
- 回播条目选择
- SOC 选择

### 方案

在 `prompter.py` 内部增加输入适配层：

- 顶层命令 REPL 直接走 `prompt_toolkit`
- 旧输入逐步从 `questionary + input()` 迁移到统一适配层

### 先做的输入能力

- 单行输入
- 命令补全
- 命令历史
- 历史建议
- 底部快捷提示
- 数字输入
- 确认输入
- 搜索式选择器

### 阶段 2 的完成标准

- 新输入不再直接散落 `input()`
- 历史记录和回播库选择能逐步接入更强交互

## 阶段 3：列表页与命令页协同增强

### 目标

让历史和回播条目“像工具”，不是“像打印文本”。

### 范围

- 历史浏览
- 历史回播选择
- 自动扫描回播条目选择
- 全量模式 Tag 选择
- `history` 等少量子命令支持

### 方案

- 历史浏览继续保留 `less`
- 选择回播可以逐步接入 `prompt_toolkit`
  - 模糊搜索
  - 快速过滤
  - 快捷键

### 交互方向

- 输入关键字过滤
- 回车确认
- Esc / 空输入返回
- 命令 + 少量子命令组合
  - 例如 `history`
  - 例如 `history last`
  - 例如 `history 3`
  - 例如 `history clear`

## 阶段 4：准 TUI 页面统一

### 目标

在不引入完整事件驱动框架的前提下，形成统一的“页面感”。

### 页面结构

- 顶部：标题 / 当前环境
- 中部：主内容
- 底部：快捷提示 / 当前状态

### 不做的事情

- 暂不实现完整窗口管理
- 暂不实现鼠标交互
- 暂不实现复杂异步刷新

## 文件级改造计划

### `interface/ui.py`

职责：

- 统一 Rich Console
- 提供 render/print/browse 三类接口

计划：

- 建 Rich Theme
- 替换 banner/status/table/panel
- 把历史渲染逻辑统一收口

### `interface/prompter.py`

职责：

- 输入适配层

计划：

- 保留现有接口名，内部逐步替换实现
- 增加命令 REPL 输入会话
- 逐步把旧的 `questionary` 限缩到兼容层

### `interface/replay_prompter.py`

职责：

- 回播领域输入

计划：

- 后续优先把历史选择、回播条目选择做成更友好的选择器

### `interface/cli.py`

职责：

- 命令 REPL 顶层循环

计划：

- 只负责命令分发
- 不在这里堆叠业务逻辑
- 不再以菜单树为主

## 风格指导

### 视觉方向

- 终端风格要清晰、克制、现代
- 不是花哨，而是易扫读

### 展示原则

- 重要信息优先
- 长文本可折叠到 `less`
- 不重复展示无信息量字段

### 配色原则

- 成功：绿色系
- 警告：黄色系
- 错误：红色系
- 结构信息：青色/蓝色系

## 风险与处理

### 风险 1：Rich 和当前 ANSI 混用

处理：

- 阶段 1 内优先清理 `ui.py` 中直接输出 ANSI 的地方

### 风险 2：输入层切换太快，影响现有流程

处理：

- 先展示层，后输入层
- 输入接口名保持兼容

### 风险 3：less 与 Rich 渲染不一致

处理：

- `less` 继续以文本视图为主
- 复杂 Rich 布局只用于直出，不强求进入 `less`
